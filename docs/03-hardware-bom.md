# 03. 하드웨어 BOM

> English: [03-hardware-bom_eng.md](03-hardware-bom_eng.md)

가격은 2026년 기준 대략치. 확정 전 재확인 필요.

## 보드 선택지

| 보드 | 스펙 | 판단 |
|---|---|---|
| Uno R3 (ATmega328P) | 16 MHz, SRAM 2 KB | Q-learning은 되지만 TinyML 불가. 확장 여지 없음 |
| **Nano 33 BLE Sense Rev2** | nRF52840 M4F 64 MHz, RAM 256 KB, IMU·마이크·근접센서 내장 | 아두이노 공식 TinyML 보드. 센서가 이미 붙어 있어 배선이 준다 |
| Uno R4 WiFi | RA4M1 48 MHz + ESP32-S3(WiFi) | 무난. 텔레메트리를 무선으로 뽑기 좋음 |
| **ESP32-S3** | 듀얼코어 240 MHz, PSRAM, ESP-NN 가속 | 가성비 최고. 카메라·WiFi 포함. 코어 1개를 제어 루프 전용으로 고정 가능 |
| Raspberry Pi Zero 2 W | 리눅스, 쿼드코어 | 호스트 계층을 로봇에 태울 때 |

**추천**: ESP32-S3를 MCU 계층으로. 듀얼코어라 제어 루프(코어 0)와 통신(코어 1)을
물리적으로 분리할 수 있는 게 결정적이다. 아키텍처 문서의 "루프 지터" 문제가
설계 단계에서 해소된다.

## 구동계

| 부품 | 선택 | 비고 |
|---|---|---|
| 섀시 | 2WD 로봇카 키트 | 4WD는 회전 시 슬립이 커서 오도메트리가 나빠진다 |
| 모터 드라이버 | **TB6612FNG** 또는 DRV8833 | **L298N 비추** — 전압강하 1.4 V 이상, 발열 심함 |
| 모터 | N20 기어드 DC + **엔코더** | 엔코더는 선택이 아니라 필수. 아래 참조 |
| 바퀴 | 키트 동봉 + 캐스터 | |

### 엔코더가 필수인 이유

보상 함수가 "전진하면 +1"인데, 실제로 전진했는지를 모르면 보상이 거짓말을 한다.
벽에 밀착해 바퀴만 헛도는 상태에서 로봇은 계속 +1을 받고, 학습은 "벽에 붙어
있기"로 수렴한다. 엔코더 없이 이 프로젝트를 하면 이 버그를 반드시 만난다.

## 센서

| 부품 | 용도 | 비고 |
|---|---|---|
| **VL53L0X ToF** × 2~3 | 전방/좌/우 거리 | 초음파(HC-SR04)보다 정확하고 빠름. I2C 주소 충돌 주의 — XSHUT 핀으로 순차 초기화 필요 |
| MPU6050 또는 BMI270 IMU | 자세, 충돌 감지 | 급감속 = 충돌. 별도 범퍼 없이도 충돌 보상 계산 가능 |
| 범퍼 스위치 × 2 | 하드 충돌 감지 | 인터럽트로 연결. 학습 대상이 아니라 안전장치 |
| (선택) 낭떠러지 IR × 2 | 추락 방지 | 책상 위에서 학습시킬 거면 필수 |

## 전원 — 가장 흔한 실패 지점

| 부품 | 사양 |
|---|---|
| 배터리 | 18650 × 2 (7.4 V) + 홀더 |
| 로직 레귤레이터 | 배터리 → 5 V/3.3 V, 모터 전원과 **분리** |
| 커패시터 | 모터 전원에 1000 µF 이상 + 각 모터 단자에 0.1 µF |
| 보호 | BMS 내장 배터리 또는 별도 보호회로 |

> **⚠️ 모터를 보드의 5 V 핀에서 먹이지 말 것.**
> 모터 기동 전류가 순간적으로 레일을 끌어내려 브라운아웃 리셋을 일으킨다.
> 학습 중에 리셋이 나면 RAM의 Q 테이블이 통째로 날아가고, 증상은
> "왜 학습이 안 되지"로 나타난다. 원인 추적에 며칠 걸리는 종류의 버그다.
> 모터 전원과 로직 전원을 분리하고, GND만 공통으로 묶는다.

## 안 1 선택 시 알아야 할 것

### ⚠️ 펌웨어 수정이 필요하다

#3543은 **DRV8838** 드라이버 2개를 쓴다. 인터페이스가 DIR + PWM (phase/enable)이라,
현재 `firmware/src/drive/motors.cpp`의 TB6612FNG 방식(IN1/IN2 + PWM)과 다르다.
모터당 핀이 3개에서 2개로 줄어드는, 오히려 단순해지는 변경이지만 코드는 고쳐야 한다.
(배선 전에 #3543 핀아웃 도면으로 최종 확인할 것.)

### counts/m 예상값

Romi 엔코더는 모터축 1회전당 12카운트(양 채널 양 엣지 = 4체배 기준).
현재 펌웨어는 A채널 양 엣지만 세는 2체배이므로 모터축 1회전당 6카운트.

```
6 counts/rev × 120:1 기어비 = 720 counts / 바퀴 1회전
바퀴 지름 70 mm → 원주 0.2199 m
720 / 0.2199 = 약 3274 counts/m
```

`cfg::kDefaultCountsPerMeter`의 자리표시자 3000과 가깝다.
그래도 **`cal` 명령으로 실측 보정할 것.** 계산값은 시작점일 뿐이다.

### 배터리는 NiMH로

6×AA 슬롯에 알칼라인을 넣으면 9 V다. Romi의 미니 플라스틱 기어모터 정격을
넘어서므로 수명이 짧아진다. NiMH 6개면 7.2 V로 적당하고, 학습 실험은 주행 시간이
길어서 어차피 충전지가 필요하다.

### 재고

Adafruit의 ESP32-S3-DevKitC-1 재판매 상품([#5312](https://www.adafruit.com/product/5312))은
확인 시점에 품절이었다. DigiKey / Mouser / Amazon 쪽이 낫다.
N8, N8R8 어느 쪽이든 무방하다 — PSRAM은 안 쓴다. 다만 N8R8은 옥탈 PSRAM이
GPIO 33–37을 쓰므로, 이미 그 핀들을 피해 둔 `include/pins.h`를 그대로 유지할 것.
