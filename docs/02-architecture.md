# 02. 아키텍처

> English: [02-architecture_eng.md](02-architecture_eng.md)

## 2계층 분리

```
┌─────────────────────────────────────────┐
│  Host  (PC / 라즈베리파이)               │
│  · 무거운 학습 (PPO, 시뮬레이션)          │
│  · 텔레메트리 수집·시각화                 │
│  · 정책 컴파일 → 보드로 배포              │
└────────────────┬────────────────────────┘
                 │ USB serial / WiFi  (비실시간, 끊겨도 됨)
┌────────────────┴────────────────────────┐
│  MCU                                     │
│  · 고정 주기 제어 루프 (50 Hz)            │
│  · 센서 읽기 → 정책 실행 → 모터 출력      │
│  · 온디바이스 Q-learning                  │
│  · 안전 정지 (호스트가 죽어도 동작)       │
└─────────────────────────────────────────┘
```

## 왜 나누는가

**MCU 혼자 다 하면 벽에 부딪힌다.** 카메라를 붙이는 순간 메모리가 부족하고,
WiFi 스택이 제어 루프의 주기를 흔든다. 제어 주기가 흔들리면 학습된 정책이
실기에서 무너진다 — Microduck이 50 Hz를 고정해 두는 이유다.

**호스트 혼자 다 하면 안전하지 않다.** WiFi가 끊기거나 파이썬이 GC로 멈추는
동안 로봇은 벽으로 달려간다. 안전 정지는 반드시 MCU에 있어야 한다.

**나중에 갈아끼우기 쉽다.** 무거운 것을 위층에 두면, 3단계에서 5단계로 갈 때
MCU 코드는 그대로 두고 위층만 바꾸면 된다.

## 계층 간 계약

MCU가 진실의 원천(source of truth)이다. 호스트는 조언자일 뿐이다.

| 방향 | 내용 | 주기 |
|---|---|---|
| MCU → Host | 상태, 행동, 보상, 센서 원값 (텔레메트리) | 매 스텝 |
| Host → MCU | 새 정책 가중치 / Q 테이블, 하이퍼파라미터 | 비정기 |
| Host → MCU | 수동 조종 명령 (디버깅용) | 비정기 |

호스트로부터 N ms 동안 아무것도 오지 않으면 MCU는 자율 모드를 유지한다.
연결 상실은 오류가 아니라 **정상 상태**로 취급한다.

## 학습 모드 두 가지

### A. 온디바이스 (Q-learning)

```c
// 상태 36 × 행동 4 × int16(0.01 단위) + 헤더 = 304 바이트.
Q[s][a] += alpha * (reward + gamma * max_a2(Q[s2][a2]) - Q[s][a]);   // alpha 0.2, gamma 0.9
```

구현: `firmware/src/learn/qlearn.cpp` (하드웨어를 모르는 순수 로직), 주행 연결은
`control_loop.cpp`의 `stepLearn()`. 콘솔 `l` 학습 주행 / `q` 테이블 / `qs` 저장 / `qz` 초기화.

- 상태: 전방 거리 3구간(135 / 300 mm 경계) × 측면(열림 / 왼쪽 벽 / 오른쪽 벽) × 직전 행동
  - ⚠️ 센서가 바닥을 보는 동안(바닥이 ~180 mm로 읽힘)은 전방이 거의 늘 가운데 구간이라,
    학습기가 구분하는 건 사실상 "아주 가까움 / 아님" 뿐이다. 학습이 약하면 센서 각도부터 의심.
- 행동: 전진 / 좌회전 / 우회전 / 후진 — 하나 고르면 200 ms 유지
- 보상 (초안): 엔코더 전진 1 m당 +30, 회전 −0.1, 전방 너무 가까움 −1, 접촉 −10
  - 범퍼가 없어서 **접촉 = "세 거리값이 2초간 25 mm 안에서만 변함"** 으로 판단
  - ⚠️ 엔코더만 믿으면 안 된다 — 벽에 밀착한 채 바퀴가 헛돌면 전진 점수가 나온다.
    그래서 접촉이 감지된 스텝은 전진 점수를 0으로 한다. 완전한 교차 검증은 센서 각도가
    고쳐져 전방 거리가 실제 물체를 볼 때 가능하다.
- 탐험: ε 0.30에서 스텝마다 ×0.999, 최소 0.05. 테이블과 함께 저장되어 재부팅해도 이어짐
- 갇힘: 10초간 진전이 없으면 정해진 후진+회전으로 빼내고 학습은 계속 (그 구간은 학습 안 함)
- 지속성: 60초마다, 그리고 세션이 끝날 때 EEPROM에 저장
  - ⚠️ R4의 EEPROM은 **바뀐 바이트 하나에 약 44 ms** (실측). 한 번에 쓰면 제어 루프가
    수 초간 멈춘다 (2.8 s, 빈 영역에 처음 쓸 땐 13.5 s 측정). 그래서 **루프 한 바퀴에
    1바이트씩** 나눠 쓰고, 바뀌지 않은 바이트는 건너뛴다.

이것만으로 "명령 없이 움직이면서 스스로 나아지는 로봇"이 완성된다.

### B. 오프디바이스 (sim-to-real)

```
시뮬레이터에서 PPO 학습 → 양자화 → C 배열 또는 ONNX → MCU는 추론만
```

Microduck과 같은 방식. 신경망이 필요해지는 4~5단계에서 도입한다.

## 설계 규칙

1. **제어 루프는 절대 블로킹하지 않는다.** `delay()` 금지, 로깅도 논블로킹.
2. **보상 계산은 MCU에서 한다.** 호스트에 맡기면 지연이 학습을 오염시킨다.
3. **탐험(exploration)에는 물리적 안전장치를 건다.** ε-greedy가 로봇을
   계단에서 떨어뜨릴 수 있다. 낭떠러지 센서와 범퍼는 학습 대상이 아니라
   하드 인터럽트다.
4. **모든 실험은 시드를 기록한다.** 재현되지 않는 학습 결과는 결과가 아니다.
