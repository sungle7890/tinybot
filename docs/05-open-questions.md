# 05. 미결정 사항

> English: [05-open-questions_eng.md](05-open-questions_eng.md)

Phase 1로 넘어가기 전에 정해야 하는 것들. 정해지면 이 문서에 결정과 근거를 남긴다.

## Q1. 보드 — 어디까지 갈 것인가 ★ 가장 중요

| 안 | 내용 | 얻는 것 | 잃는 것 |
|---|---|---|---|
| **A. MCU 단독** (ESP32-S3) | 아두이노 프로젝트로 끝까지 | 저비용, 전력 이해도, 실시간 제어 감각 | 비전 불가, 5단계 어려움 |
| **B. MCU + 호스트 PC** | MCU는 제어, 학습은 노트북 | A의 장점 + 무거운 학습 가능 | 무선 의존, 로봇이 PC에 묶임 |
| **C. MCU + Pi Zero 2 W** | 호스트를 로봇에 탑재 | 완전 자율 + 비전 | 비용·무게·전력 증가 |
| **D. Microduck 구매** | $399 | 즉시 최신 RL 로봇 | 만드는 재미가 없음. 배움이 얕아짐 |

**결정: A (ESP32-S3 단독).** 2026-09-04.
B·C는 폐기가 아니라 보류다. A→B→C는 같은 하드웨어 위에서 순차 확장이 가능하도록
[02-architecture.md](02-architecture.md)의 2계층 구조를 잡아뒀다.
A로 시작해도 나중에 C로 가는 데 낭비가 없다.

D는 "만들기"가 아니라 "쓰기"이므로 이 프로젝트의 목표와 다르다.
다만 오픈소스이므로 **구매하지 않고 코드만 읽는 것**은 강력히 권장한다.

## Q2. 비전(카메라)이 필요한가

- 필요 없다면 → ESP32-S3 또는 Nano 33 BLE Sense, 어느 쪽이든 무방
- 필요하다면 → ESP32-S3(저해상도 한정) 또는 Pi 계열이 사실상 강제

**결정: 지금은 안 쓴다.** 2026-09-04.
3단계 Q-learning에는 카메라가 필요 없다. ESP32-S3를 골랐으므로
나중에 저해상도 카메라를 붙이는 선택지는 열려 있다.

## Q3. 로코모션 — 바퀴인가 다리인가

Microduck은 서보 15개 이족이다. 매력적이지만:

- 이족 보행은 실기 시행착오로 학습시킬 수 없다 (로봇이 부서진다)
- 반드시 시뮬레이터가 먼저 필요하다 → 5단계 선행
- 학습 자체보다 기구·제어에 시간의 대부분이 들어간다

**결정: 2WD 바퀴.** 2026-09-04.
 "학습이 일어나는가"를 검증하는 데 집중할 수 있다.
다리는 3단계를 끝낸 뒤 별도 프로젝트로.

## Q4. 펌웨어 언어

| 안 | 판단 |
|---|---|
| **C++ / Arduino (PlatformIO)** | 자료·라이브러리 압도적. 기본값 |
| Rust (esp-hal) | Microduck과 같은 선택. 안전하지만 임베디드 생태계 학습 비용이 크다 |
| MicroPython | 프로토타이핑은 빠르나 50 Hz 결정론적 루프에 부적합 |

**결정: PlatformIO + C++.** 2026-09-04.
첫 임베디드 프로젝트에서 언어까지 새로 배우면
디버깅 시 "내 로직 문제인가 언어 문제인가"를 구분하기 어렵다.

## Q5. 예산 상한

A안 기준 약 10~12만원. Pi Zero 2 W는 보류했으므로 추가 비용 없음.
