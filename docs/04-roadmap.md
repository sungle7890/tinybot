## Phase 0 — 설계 · 부품 확정 ✅

- [x] 보드 확정 — A안, ESP32-S3 단독 ([05-open-questions.md](05-open-questions.md))

## Phase 1 — 하드웨어 브링업 ← **현재**

> 펌웨어는 작성·컴파일 완료. 아래 항목은 전부 **실기 검증** 항목이므로
> 부품이 도착해야 체크할 수 있다. 절차는 [../firmware/README.md](../firmware/README.md).

- [x] PlatformIO 프로젝트 생성, 빌드 파이프라인 (`pio run` 성공)
- [ ] 업로드 확인
- [ ] 모터 양방향 구동 + PWM 속도 제어
- [ ] 엔코더 카운트 읽기 → 실제 이동거리(mm) 환산
- [ ] ToF 3개 동시 동작 (I2C 주소 재할당)
- [ ] IMU 읽기
- [ ] 고정 주기 50 Hz 루프 (지터 측정해서 기록)

**완료 조건**: 1 m 직진 명령 시 실측 오차 ±5 % 이내.
루프 주기 지터가 50 Hz 기준 ±2 ms 이내.

> 여기서 오도메트리가 부정확하면 3단계 보상이 통째로 거짓말이 된다.
> 대충 넘어가면 안 되는 유일한 단계.

## Phase 2 — 규칙 기반 자율주행

- [ ] Braitenberg / subsumption 방식으로 장애물 회피
- [ ] 범퍼·낭떠러지 하드 인터럽트 안전 정지
- [ ] 시리얼 텔레메트리 스트리밍 (`host/`에서 그래프)

**완료 조건**: 명령 없이 10분간 방 안을 돌아다니며 충돌 3회 이하.

> **여기서 이미 "명령 없이 자율적으로 움직이는 로봇" 목표는 달성된다.**
> 자율성은 AI를 요구하지 않는다. 이 사실을 확인하고 넘어가야
> 3단계에서 "AI가 뭘 더해줬는지"를 정직하게 평가할 수 있다.
> 2단계 성능이 3단계 비교 기준선(baseline)이 된다.

## Phase 3 — 온디바이스 Q-learning ★ 프로젝트의 핵심

- [ ] 상태 이산화 설계 및 구현
- [ ] Q 테이블 + ε-greedy 탐험 (ε 감쇠 스케줄)
- [ ] 보상 함수 (엔코더 기반 실제 전진량 사용)
- [ ] EEPROM/Flash 체크포인트 → 전원 재투입 후 유지 확인
- [ ] 호스트에서 학습 곡선 실시간 플롯

**완료 조건**:
1. 학습 곡선이 우상향하고, 서로 다른 시드 3회에서 재현된다.
2. 학습 후 성능이 **2단계 규칙 기반 baseline을 넘는다.**
3. 전원을 껐다 켜도 학습된 행동이 유지된다.

> 2번이 진짜 관문이다. 넘지 못하면 "학습은 했지만 손으로 짠 규칙보다 못한"
> 상태인데, 그것도 정직한 결과다. 그 경우 상태 표현이나 보상 설계를 의심한다.

## Phase 4 — TinyML 추론 (선택)

- [ ] Edge Impulse 또는 TFLite Micro 파이프라인 구축
- [ ] 제스처 또는 음성 명령 인식 → 로봇 행동에 연결
- [ ] 추론 지연 측정, 50 Hz 루프에 영향 없는지 확인

**완료 조건**: 인식 정확도 90 % 이상이면서 제어 루프 지터가 1단계 기준 유지.

## Phase 5 — sim-to-real (선택, Microduck 방식)

- [ ] MuJoCo 또는 PyBullet에 로봇 모델링
- [ ] PPO로 정책 학습
- [ ] ONNX export → MCU용 C 배열로 양자화
- [ ] 실기 배포, sim-to-real 갭 측정

**완료 조건**: 시뮬레이션에서 학습한 정책이 실기에서 동작한다
(성능 저하는 허용, 완전 실패는 불가).

## 중단 지점

**3단계까지가 이 프로젝트의 본체다.** 4·5단계는 흥미가 남아 있으면 간다.
3단계를 제대로 끝내면 "동작을 학습하고 명령 없이 자율적으로 움직이는 로봇"이
실제로 손에 있다. 그게 원래 목표였다.
