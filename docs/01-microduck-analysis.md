# 01. Microduck은 실제로 어떻게 AI를 돌리는가

> English: [01-microduck-analysis_eng.md](01-microduck-analysis_eng.md)

출처: [pollen-robotics.com/microduck](https://pollen-robotics.com/microduck/),
[github.com/pollen-robotics/microduck](https://github.com/pollen-robotics/microduck)

## 핵심 정정

**Microduck은 마이크로컨트롤러에서 AI를 돌리는 제품이 아니다.**
설계 어디에도 아두이노나 보조 MCU가 없다. 리눅스가 도는 ARM SoC 한 개가
서보 버스를 직접 물고 전부 처리한다.

이 사실이 우리 프로젝트의 전제를 바꾼다. "저런 작은 보드에서 AI가 도는구나"가
아니라 "작은 **리눅스 컴퓨터**에서 사전 학습된 정책을 추론만 돌리는구나"가 맞다.

## 실측 스펙

| 항목 | 내용 |
|---|---|
| 컴퓨트 | Rockchip RK3566 (ARM SoC, 리눅스) |
| 크기 / 무게 | 25 cm / 800 g |
| 액추에이터 | 서보 15개, 서보 버스로 직결 |
| 센서 | 카메라, 8×8 ToF 뎁스 센서, IMU 2개 |
| 제어 루프 | 온보드 50 Hz 정책 루프 |
| 정책 포맷 | ONNX |
| 펌웨어 언어 | Rust (단일 워크스페이스, 데몬 여러 개) |
| 학습 | MuJoCo + PPO (`microduck_rl` 별도 레포) |
| 라이선스 | Apache-2.0, 정책 7종 전부 공개·재학습 가능 |
| 가격 | $399 (도입가, 세금·배송 별도) |

## 소프트웨어 구조

데몬들이 Unix 소켓 위의 JSON-RPC 계약으로 통신한다.

| 데몬 | 역할 |
|---|---|
| `robotd` | 모터 제어 루프, 서보 버스 관리 |
| `updaterd` | 서명된 릴리스 설치 및 롤백 |
| `configd` | WiFi / 아이덴티티 설정 |
| `btd` / `padd` | 블루투스 / 게임패드 입력 |
| `mediad` | WebRTC 카메라 스트리밍 |
| `tofd` | 뎁스 센서 |

## 파이프라인

```
MuJoCo 시뮬레이션에서 PPO로 학습
        ↓
ONNX로 export
        ↓
실기에 배포 → 50 Hz로 추론만 수행
```

즉 **sim-to-real**이다. 실기에서 역전파가 돌지 않는다.
걷기·앉기·차기·집기·롤러스케이팅·낙상 복구 전부 이 방식으로 만들어진 신경망 정책.

## 우리가 가져올 것

- **sim-to-real 파이프라인** — 실기에서 시행착오를 반복하면 로봇이 부서진다.
  시뮬레이션에서 수백만 스텝 돌리고 결과만 옮기는 게 정석.
- **고정 주기 정책 루프** — 50 Hz는 좋은 기준점. 제어 주기를 흔들리게 두면
  학습된 정책이 실기에서 무너진다.
- **ONNX를 정책 교환 포맷으로** — 학습 프레임워크와 실행 런타임을 분리.
- **데몬 분리 구조** — 제어 루프를 카메라·네트워크와 같은 프로세스에 두지 않는다.
  Apache-2.0이니 구조를 그대로 참고해도 문제없다.

## 우리가 가져올 수 없는 것

- 서보 15개 이족 보행. 첫 프로젝트로는 난이도가 몇 단계 위다.
  바퀴 2개로 시작하면 학습 자체에 집중할 수 있다.
- RK3566급 컴퓨트. 이걸 쓰겠다면 그건 아두이노 프로젝트가 아니라
  라즈베리파이 프로젝트다 — 그것도 유효한 선택이지만, 선택은 선택이다.

## 결론

Microduck은 "MCU에서 AI가 돈다"의 증거가 아니라
**"작은 리눅스 보드 + 사전 학습 정책 추론"의 좋은 참고 설계**다.
그리고 전부 오픈소스라, 구매하지 않아도 코드를 읽고 배울 수 있다.
