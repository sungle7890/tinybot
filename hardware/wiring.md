# A. UNO R4 WiFi (현재)

## 이 배치를 결정한 두 가지 제약

1. **외부 인터럽트가 D2/D3 둘뿐.** 그래서 엔코더 A채널만 인터럽트를 쓰고,
   범퍼는 제어 틱마다 폴링한다. 벽에 눌린 스위치는 20 ms보다 훨씬 오래
   닫혀 있어 놓치지 않는다.
2. **I2C를 Qwiic으로.** Qwiic은 두 번째 버스(`Wire1`)이고 3.3 V 전용이다.
   헤더 핀을 쓰지 않아 A4/A5가 비고, 그래야 18핀이 들어간다.

## 핀 배정 (R4 WiFi)

|---|---|---|

| **D3** | 우 엔코더 A | **인터럽트** |
| D4 | 좌 엔코더 B | |
| D5 | 좌 모터 PWMA | PWM |
| D6 | 우 모터 PWMB | PWM |
| D7 | 좌 AIN1 | |
| D8 | 좌 AIN2 | |
| D9 | 우 BIN1 | |
| D10 | 우 BIN2 | |
| D11 | 모터 STBY | |
| D12 | 우 엔코더 B | |
| D13 | (예비) | 온보드 LED가 물려 있어 입력엔 부적합 |
| A0 | ToF XSHUT 전방 | |
| A1 | ToF XSHUT 좌 | |
| A2 | ToF XSHUT 우 | |
| A3 | 좌 범퍼 → GND | 폴링, INPUT_PULLUP |
| A4 | 우 범퍼 → GND | I2C가 Qwiic이라 비어 있음 |
| A5 | (예비) | |
| **Qwiic** | VL53L0X ×3 + MPU-6050 | `Wire1`, **3.3 V 전용** |

**사용 18 / 가용 18 + 예비 2.**

## Qwiic 체인

Adafruit VL53L0X(#3317)와 MPU-6050(#3886)은 STEMMA QT 커넥터가 있어
Qwiic과 호환된다. **I2C 납땜이 없다.**

```
R4 Qwiic ─ VL53L0X(전방) ─ VL53L0X(좌) ─ VL53L0X(우) ─ MPU-6050
```

⚠️ XSHUT은 Qwiic 케이블에 없다. 센서마다 A0/A1/A2로 **개별 배선**이 필요하다.

⚠️ **Qwiic에 5 V를 넣으면 보드가 망가진다.** 3.3 V 전용이다.

> 헤더 I2C(A4/A5, 5 V)를 쓰고 싶으면 `cfg::kUseQwiic`을 false로 두고,
> 우 범퍼를 A4에서 D13으로 옮긴다.

## 전원 (R4 WiFi)

```
Romi 6×AA NiMH (7.2 V) ─→ #3541 전원 보드 (역전압 보호 + 스위치)
                              └─ VSW ─┬─→ TB6612FNG VM   (모터)
                                      └─→ R4 VIN         (로직, R4가 레귤레이션)
R4 5V ─→ TB6612 VCC, 인코더 VCC (최소 3.5 V라 3.3 V 불가)
GND 전부 공통
```

전체 연결표와 조립 순서는 **[assembly.md](assembly.md)**.

> **⚠️ 모터를 R4의 5 V 핀에서 먹이지 말 것.** 아래 전원 항목과 동일한 이유다.

# B. ESP32-S3 (Phase 4용 보류)

## 핀 배정 (잠정 — 실물 보드와 대조 필요)

### TB6612FNG 모터 드라이버

| ESP32-S3 | TB6612FNG | 비고 |
|---|---|---|
| GPIO 17 | STBY | LOW면 출력 차단 |
| GPIO 4 | PWMA | 좌측 |
| GPIO 5 | AIN1 | |
| GPIO 6 | AIN2 | |
| GPIO 7 | PWMB | 우측 |
| GPIO 15 | BIN1 | |
| GPIO 16 | BIN2 | |
| 3V3 | VCC | 로직 |
| — | VM | **모터 배터리에서 직결. 보드 5V 아님** |
| GND | GND | 로직·모터 GND 공통 |

### 엔코더

| ESP32-S3 | 신호 |
|---|---|
| GPIO 8 | 좌 A (인터럽트) |
| GPIO 9 | 좌 B |
| GPIO 10 | 우 A (인터럽트) |
| GPIO 11 | 우 B |

내부 풀업 사용. 엔코더가 오픈 컬렉터면 그대로, 푸시풀이면 그래도 무방.

### I2C

| ESP32-S3 | 신호 |
|---|---|
| GPIO 13 | SDA |
| GPIO 14 | SCL |

400 kHz. 풀업 4.7 kΩ — 대부분의 브레이크아웃 보드에 이미 달려 있다.
**세 개를 병렬로 달면 풀업이 너무 세진다.** 한 보드만 남기고 나머지는 제거하거나,
그대로 두려면 실제 파형을 확인할 것.

### VL53L0X XSHUT

| ESP32-S3 | 센서 | 부팅 후 주소 |
|---|---|---|
| GPIO 1 | 전방 | 0x30 |
| GPIO 2 | 좌 | 0x31 |
| GPIO 42 | 우 | 0x32 |

세 개 모두 0x29로 부팅하므로 하나씩 XSHUT을 풀어 재주소 지정한다
(`firmware/src/sense/tof.cpp`).

### 범퍼

| ESP32-S3 | 신호 |
|---|---|
| GPIO 41 | 좌 범퍼 → GND |
| GPIO 40 | 우 범퍼 → GND |

노멀 오픈, INPUT_PULLUP, FALLING 인터럽트. 30 ms 소프트웨어 디바운스.

## 피한 핀과 이유

| 핀 | 이유 |
|---|---|
| 0, 3, 45, 46 | 스트래핑 핀 |
| 19, 20 | 네이티브 USB D−/D+ |
| 26–32 | SPI 플래시 |
| 33–37 | N8R8/N16R8 모듈의 옥탈 PSRAM |
| 43, 44 | UART0 (콘솔) |

## 전원

```
18650 ×2 (7.4 V)
   ├─→ TB6612FNG VM        (모터)
   └─→ 5V 레귤레이터 ─→ ESP32-S3 5V 핀   (로직)
GND 공통
```

- TB6612FNG VM에 1000 µF 이상, 각 모터 단자에 0.1 µF 세라믹
- 배터리는 BMS 내장품 사용

> **⚠️ 모터를 보드 5 V 핀에서 먹이지 말 것.**
> 기동 전류가 레일을 끌어내려 브라운아웃 리셋을 낸다. Phase 3에서 이게 나면
> RAM의 Q 테이블이 통째로 날아가고, 증상은 "학습이 안 된다"로만 보인다.
> 원인 추적에 며칠 걸리는 종류의 버그다.
